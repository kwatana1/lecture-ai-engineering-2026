## 宿題

- 取り組んだレベル：基礎

- 変えた設定やデータ：
  CONFIG の `lora_r` を 16 から 8 に変更（lr や num_train_epochs など他のハイパーパラメータは初期値のまま維持）。

- 結果（比較表や数字）：
  | 項目 | 元の設定 (lora_r=16) | 変更後 (lora_r=8) |
  | :--- | :--- | :--- |
  | format_rate | 1.0 (21/21) | 1.0 (21/21) |
  | content_rate | 0.905 (19/21) | 0.905 (19/21) |
  | 最終 loss | 約 0.28 | 約 0.32 |
  | 学習時間 | 約 190秒 | 約 175秒 |

  LoRA のランク（r）を 16 から 8 に半減させたところ、学習時間はわずかに短縮し最終 loss は微増したものの、形式遵守率（format_rate）は 1.0 のまま維持され、内容正解率（content_rate）も 0.905 と変化しなかった。今回のタスク規模（JSON形式の強制および小規模FAQ）においては、r=8 でも十分に表現力を保てることが確認できた。

- ファインチューニングが向く場面・向かない場面についての考察：
  - 向く場面：JSON構造や特定のタグ形式の出力、キャラクター付けや口調・語尾の固定など、「出力フォーマットやスタイル・行動規範を厳密に守らせたい場合」。少量の学習データでもベースモデルの挙動を効率的に補正できる。
  - 向かない場面：FAQに含まれない未知の知識の記憶、頻繁に更新される最新情報の反映、または事実関係の正確な真偽判定。モデル単体で知識を正しく記憶・判定させるのは難しく幻覚（ハルシネーション）のリスクがあるため、知識の補強には外部検索やRAG、エージェントのツール活用を組み合わせる方が適している。
